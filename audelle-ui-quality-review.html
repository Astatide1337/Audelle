Design system audit

Audelle now has one visual language for actions, fields, surfaces, typography, focus states, and motion. This review records the decisions, the local evidence, and the boundaries that still depend on the audio provider.

Reviewed 21 August 2026 Scope: home, filters, transition, slideshow, export, visualizer Mode: local source and preview review

Verdict

Consistent locally

Shared UI tokens now own the repeated decisions: primary actions, muted surface controls, icon controls, form fields, menus, dialogs, links, display type, focus rings, and motion timing. The info control and New search use the same surface treatment.

Findings

Changes verified

Resolved

Controls now follow explicit semantic roles.

Button variants cover primary, surface, ghost, outline, and icon controls. The same token set owns radii, minimum heights, focus rings, hover lift, pressed scale, disabled opacity, and reduced-motion behavior.

Evidence: Button.tsx, buttonClassNames.ts, and index.css.

Resolved

Surface and typography decisions are centralized.

Home input, filter dialog, export status, tooltip, and the slideshow controls use shared surface tokens. Display headlines use type-display; compact labels continue to use label-meta. This removes the previous near-duplicate one-off color and spacing strings.

Evidence: live home, modal, and slideshow screenshots in the local preview.

Resolved

Ambient motion and micro-interactions have a controlled rhythm.

The red ember glow now drifts slowly through a 52-second, multi-waypoint path that crosses the canvas instead of oscillating between two corners. Controls lift on hover, compress on press, and animate focus and field emphasis. The filter dialog and popularity menu retain enter/exit motion and the reduced-motion media query disables decorative movement.

Boundary

The visualizer is playback-synced, not raw frequency analysis.

YouTube’s sanctioned IFrame API exposes playback state and current time, but not PCM samples or FFT data from its cross-origin player. Audelle therefore uses a deterministic, per-track bar rhythm driven by the actual playback clock. True beat amplitude requires a same-origin audio source or an uploaded/approved stream that can be connected to Web Audio.

Five-axis review

Assessment

  • Correctness: controls retain keyboard focus behavior, filter validation, modal focus trapping, and playback-next handling.
  • Readability and architecture: semantic tokens live in one CSS layer; component code composes roles instead of repeating visual recipes.
  • Security: export links retain noopener/noreferrer; external provider integration stays behind the sanctioned YouTube IFrame/API boundary.
  • Performance: visualizer bar profiles are memoized per track and only playback time is polled; no document overflow was measured.
  • Copy: approved home copy and filter wording remain short and direct; status copy says “Creating playlist.”
Proven locally: source review, local build/lint, browser screenshots, computed-style checks, overflow checks, and playback-driven DOM sampling. Unknown: production behavior, OAuth approval, and provider-level audio samples.
