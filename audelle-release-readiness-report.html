What changed

Export

Valid multi-track ZIPs

The central-directory local-header offset moved from byte 38 to the ZIP-specified byte 42. The archive remains STORE-only, so already-compressed best-audio bytes are not degraded or pointlessly recompressed.

Audio quality

Original bytes, accurate formats

yt-dlp metadata now identifies the selected best-audio format. WebM/Opus, M4A, OGG, and MP3 are labeled correctly; no transcoding is introduced.

Security

Bounded stream lifetime

The four-slot audio concurrency limit now remains held through transfer completion or disconnect. Resolved URLs must be HTTPS Google Video media hosts; redirects are disabled.

Playback UX

One visual control language

Transport controls are an accessible named group and reuse Audelle’s pill controls, ember focus treatment, restrained glow, icon micro-motion, and reduced-motion path.

Catalog correctness

Provider failures degrade safely

Unknown years cannot satisfy an explicit range, malformed view strings do not crash parsing, and transient album-year failures are not permanently negative-cached.

Test discipline

Stable merge gate

Four third-party tests are marked live and skipped by default. The live year-filter smoke test must return at least one track instead of passing vacuously.

Open findings

Release blocker

Current server egress cannot export audio

A playlist generated successfully and the official IFrame player streamed it, but yt-dlp received YouTube’s “Sign in to confirm you’re not a bot” challenge for public test and freshly generated IDs. The API now returns an honest 503. Select and prove a compliant hosting/provider path; do not inject personal browser cookies as an ad-hoc production credential.

Release blocker

No Kubernetes delivery surface

No Dockerfile, image identity, Kubernetes manifests, ingress/static-host policy, CI/CD, registry, observability, or rollback artifact is declared. Nothing should be pointed at Cloudflare yet.

Medium

Public audio proxy is not playlist-bound

Any syntactically valid YouTube ID can use /api/audio/{video_id}. The stateless design has no capability proving Audelle generated that ID. Before public release, add shared edge rate/cost limits; decide separately whether signed, expiring download capabilities are worth the state/API complexity.

Medium

Body limit trusts Content-Length

The application’s 64 KiB request guard does not independently bound chunked bodies. Enforce the real receive limit at ingress and preferably at ASGI receive-stream level.

Unknown

Successful live end-to-end download

The attempted test is now concrete evidence of failure at the upstream extraction boundary. Actual codec/bitrate and OS ZIP playback can only be verified after the selected egress successfully resolves media.

Low

Test-client deprecation

The deterministic suite emits a Starlette warning that its httpx-backed TestClient path is deprecated in favor of httpx2. Schedule the compatible test-client migration before it turns into a forced dependency upgrade.

Game plan to main and production

Preview acceptance

Launch API and Vite preview together with owned test data. Exercise generation, play/pause, previous/next, restart, seek, repeat one/all/off, keyboard focus, track transition, download progress/cancel/partial failure, share/open, and mobile overflow. Record and watch a full animation cycle with reduced motion both off and on.

Resolve media egress

Choose a compliant preview/production hosting path and confirm YouTube/provider policy. Do not depend on a developer’s cookies. From the target egress, download two or more authorized tracks, open the ZIP independently, play every entry, and record container, codec, bitrate, byte size, extension, and selected yt-dlp format.

Merge gate

Review the intentionally large current migration as one release candidate, confirm deleted OAuth/export code is intentional, run server and frontend tests, web lint/build, JS and Python advisory scans, and inspect the final diff. Keep live tests in a separate provider smoke job. Then commit and push only after human approval.

Container and manifests

Choose cluster, namespace, registry, hostname, and deployment owner. Add reproducible non-root images, immutable digests, startup/readiness/liveness behavior, resource requests/limits, security context, restricted service account, NetworkPolicy, graceful termination, rollout strategy, and preview namespace overlays.

Edge, observability, rollback

Define same-origin /api routing, CSP for YouTube/player/thumbnails/fonts, forwarded-header trust, HSTS/TLS, chunked-body and sustained audio limits, structured logs, SLO dashboards, alert delivery, SBOM/image scan/provenance, and a rehearsed prior-digest rollback.

Cloudflare and production

Only after preview health: identify the real load-balancer/origin target, choose proxy/TLS mode, lower TTL early, create the scoped DNS record, and verify authoritative DNS, representative resolvers, certificate path, application route, deployed digest, reconciliation convergence, and user-visible playback/export. Do not infer success from a completed Kubernetes rollout alone.
